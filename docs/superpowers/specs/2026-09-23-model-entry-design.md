# Agent Chat 模型入口优化设计

## 目标

让用户在首次进入或尚未配置模型时能明确知道下一步，并让已有模型的切换与新增入口集中在聊天页顶部。新增模型继续复用现有模型配置表单和保存逻辑，不改变第三方 LLM 请求协议或密钥存储方式。

## 交互设计

### 1. 未配置模型

- 判定条件：可用模型列表为空。
- 顶部只显示标题 `Agent Chat`。
- 聊天内容区域中央显示空状态文案“还没有配置模型”，并提供醒目的主按钮“＋ 添加第三方 LLM”。
- 点击主按钮进入模型配置弹窗。
- 弹窗保存成功后关闭，刚保存的模型设为当前使用模型，并返回正常聊天状态。

### 2. 已配置模型

- 顶部左侧显示当前模型名称；当前模型为空时显示“选择模型”。
- 模型名称旁显示下拉指示，点击后打开模型切换菜单。
- 菜单列出所有已启用模型，当前模型带选中标识；每项可展示协议、图片/文件能力提示。
- 菜单最后固定显示“＋ 添加新模型”。点击后关闭菜单并打开同一个模型配置弹窗。
- 选择已有模型后立即切换当前模型并关闭菜单。

### 3. 模型配置弹窗

- 复用现有 `ModelConfigScreen` 的字段和 `ModelConfigViewModel` 保存、校验、密钥处理逻辑。
- 弹窗字段：显示名称、Base URL、模型名称、API Key、协议、支持图片、支持文本文件。
- 主操作为“保存并使用”；保留取消/关闭入口。
- 校验错误显示在弹窗内；保存失败时保留输入内容并展示错误，不自动关闭。
- 编辑已有配置不在本次范围内；下拉菜单只提供新增与切换。

## 实现边界

- `MainActivity` 继续负责页面状态；新增一个布尔状态控制配置弹窗，模型页不再作为新增入口的整页导航。
- `ChatScreenContent` 负责根据 `availableModels` 渲染空状态主按钮或模型下拉菜单。
- 新增模型时调用 `ModelConfigViewModel.resetForm()`，弹窗保存时调用 `save(makeDefault = true)`；保存完成后从配置列表找到新配置并调用现有 `onUse` 回调。
- 不修改 Room schema、ProviderRegistry、API Key 存储和网络请求代码。

## 验收标准

1. 空模型列表时，聊天页中央出现“＋ 添加第三方 LLM”，点击可打开配置弹窗。
2. 有模型时，顶部显示当前模型名称；点击后可看到已配置模型和最后一项“＋ 添加新模型”。
3. 点击已有模型后菜单关闭并更新当前模型名称。
4. 点击“添加新模型”或空状态按钮打开同一配置表单。
5. 配置校验失败时弹窗不关闭；保存成功后弹窗关闭并使用新模型。
6. 既有键盘回车发送、语音输入、附件入口和聊天历史入口保持不变。

## 测试计划

- Compose UI 测试：空状态按钮存在并可触发打开回调；模型菜单列出模型、显示新增项；选择模型触发回调并关闭菜单。
- 配置弹窗测试：保存成功回调使用新模型；校验错误仍留在弹窗内。
- 回归测试：现有聊天输入、停止生成、语音浮层、附件和历史测试继续通过。
